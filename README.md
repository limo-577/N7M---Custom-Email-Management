# N7M - Custom Email Management

Windows 桌面邮箱与浏览器账号管理工具，当前版本 **1.8.1**。

## 账号管理

- 左侧保留全部账号、分组、已打开三个入口；收紧页头及表格行高，默认折叠 Profile 帮助，在常用窗口尺寸下展示至少 6 个账号。
- 分组页展示全部分组、空分组及未分组，可直接新增、重命名、删除、筛选，并把勾选账号移入分组。
- 顶部同一栏放置批量录入、批量修改、添加账号、打开快捷栏、导出资料、清空全部账号、修改软件密码及锁定；冷却设置、批量启动页设定和导入资料移到侧栏底部作为备用工具。账号分组下拉位于搜索栏旁。清空全部账号仍需单独确认。
- 主界面、批量录入和批量修改窗口均有默认折叠的 Profile 帮助，可复制 `chrome://version`、`edge://version`、`brave://version`、Firefox 的 `about:profiles`。Chrome / Edge / Brave 查看 Profile Path 并填写末级目录（如 Default、Profile 43）；Firefox 填写配置名称，保留大小写，不填写目录路径。
- 点击邮箱资料、浏览器 / Profile、备注这三个表头，可分别切换升序、降序、导入顺序；排序下拉框也可直接选择字段与方向。其中浏览器列按浏览器类型排序，同类浏览器相邻。
- 邮箱资料与备注使用中文和数字自然排序，例如“账号 2”排在“账号 10”前；相同值保留原列表顺序，空值在升序与降序时都放在末尾。恢复导入顺序即可回到原排列，排序不会改写账号资料或软件编号。
- 点击账号分组直接展开下拉菜单，可筛选、添加、重命名和删除分组；分组页与下拉菜单中，点击已有分组旁的铅笔即可修改名称。重命名会同步更新组内账号的归属，分组总数保持不变，账号资料、密码、TOTP 和浏览器状态仍保留；空分组也可重命名。名称不能为空或与其他分组重复。勾选账号后可直接移入或移出分组。空分组也会保存在加密资料库中。删除分组只移除归属，保留账号、密码和 TOTP。
- 一行显示全局统计：全部账号、可启动、已打开、待完善。切换页面、搜索或分组筛选不会改变全局统计口径。
- 指定 Profile 的 Chrome、Edge、Brave 只有在新窗口携带一致的 Profile 信息时才建立窗口关联，以柔和橙色显示已打开状态。每 4 秒后台检查一次；在浏览器里关闭对应窗口后自动清除标记和计时，恢复启动按钮。窗口身份随资料库加密保存，软件锁屏或重启后重新核验。
- 主表格、已打开页、快捷栏均提供“关闭浏览器”，也支持批量关闭。仅对已确认的对应窗口发送正常关闭请求，不结束整个 Chromium 进程，不连带关闭其他 Profile。浏览器需要确认下载或未保存内容时，保留标记直到窗口真正关闭；权限不足或窗口无法确认时不会猜测关闭目标。
- 旧版缺少可靠窗口身份或 Profile 不匹配的关联会清除，不会向这些窗口发送关闭请求。Firefox、系统默认、未指定 Profile 或窗口缺少对应信息时仍可启动，但须在浏览器中手动关闭。软件不会把无法确认的窗口当作已打开账号；原关联窗口里的新标签页仍属于同一窗口。
- Firefox 留空 Profile 时使用默认配置；填写时只读校验 `%APPDATA%/Mozilla/Firefox/profiles.ini` 中已经注册且大小写一致的名称，再独立启动对应配置，避免误用另一个配置。指定配置若已在软件外运行，请先关闭该配置的窗口后再启动，不会强制结束其他配置。
- 1.7 将旧版未关联的“窗口待确认”记录迁移为不阻塞启动的“未关联窗口”提示。成功关联才计入已打开；启动检测有限重试，无法安全关联时提示原因，须在浏览器中手动关闭。已关联窗口遇到权限或检测错误时保留身份，显示“检测受限”，后台持续重试，恢复后自动更新；不会把检测失败当作已关闭。
- 快捷栏保留已打开账号，完整换行显示备注，可直接启动及关闭对应窗口；新增独立的分组下拉框，可选择全部分组、未分组及各个自定义分组，空分组也会列出并显示空状态。快捷栏分组筛选独立于主界面的搜索、标签与分组条件，切换时不会改变主界面筛选，备注及启动、关闭操作仍然保留。
- 表格列：软件编号、邮箱资料 / 密码 / TOTP / 分组、浏览器 / Profile、备注、状态 / 冷却时间、操作。
- 每行保留一个编辑图标和“启动”按钮。未设置浏览器或 Profile 格式无效时提示待完善，不自动分配浏览器。
- 启动网页可以留空，留空时直接启动浏览器；填写后打开自定义网页。支持 Chrome、Edge、Brave、Firefox 和系统默认浏览器。
- 编号留空时自动按列表顺序生成，从现有最大数字编号继续，首次从 001 开始；保留已有手动编号，删除账号不重排。旧资料的空编号在解锁时自动补齐，导入去重后才分配编号。密码与 TOTP 也是可选项，不影响已配置浏览器的账号启动。已有计时不再单独阻止启动；实际已打开时避免重复启动，关闭后恢复。
- 按邮箱、编号、浏览器、备注、分组或标签搜索；批量编辑、启动、恢复可用、导出和删除。
- 保留全局默认冷却时间与单账号覆盖，支持小数，用作参考计时。检测对应窗口关闭时自动清除计时；修改浏览器 / Profile 或删除账号前，须先关闭已经关联的窗口。

Profile 查看方法参考：[Chrome / Chromium 官方说明](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/user_data_dir.md)、[Microsoft Edge 官方说明](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/userdatadir)、[Brave 官方项目说明](https://github.com/brave/brave-browser/issues/16034)。

Profile 填写最后一级目录名，不填写完整路径。例如路径以 `User Data\Profile+21` 结尾时，填写 `Profile+21`；加号原样保留，`Profile+21` 和 `Profile 21` 是不同的目录。

## 密码、TOTP 与软件锁

首次启动需要设置至少 8 位的软件密码，随后每次启动均需解锁。软件密码可在顶部修改；Windows 锁屏或系统休眠时自动锁定，也可手动锁定。

整个资料库使用 AES-256-GCM 加密，密钥由软件密码通过 Argon2id 派生（256 MiB 内存、3 次迭代、并行度 1），每次写入使用随机 nonce。Argon2id 使用固定版本 `hash-wasm` 在独立工作线程中执行，锁定时终止未完成的派生；加密密钥只在解锁期间持有，锁定后清除密钥并重新加载界面。数据读取、修改、复制、导出和启动操作都会检查锁定状态。内部 `.bak` 同样加密，修改软件密码时同步更新；已经导出到其他位置的备份文件仍使用导出当时的软件密码。

加密算法与密码派生参考 [KeePass 安全说明](https://keepass.info/help/base/security.html)及 [VeraCrypt Argon2id 说明](https://veracrypt.io/en/Argon2id.html)。采用成熟算法不代表已经取得这些产品同等级的整体安全审计；JavaScript 中的解锁态字符串也不等同于 KeePass 的受保护内存。请使用足够长且不重复的软件密码。

编辑账号时填写登录密码和 TOTP 密钥。密码保留原样，包括前后空格。列表只显示“密码”和“TOTP”两个文字入口，不显示密码、密钥或验证码；点击密码复制登录密码，点击 TOTP 复制当前 6 位验证码。复制的凭据在 30 秒后或软件锁定时清理；若已复制其他内容，不会覆盖你的新剪贴板内容。

TOTP 支持 Base32 密钥和 `otpauth://totp` 链接，使用标准 SHA1 / 6 位 / 30 秒算法。电脑时间需要准确。软件密码无法找回，请妥善保管；丢失软件密码就无法解密资料。

## 数据与升级

为兼容安装版和免安装版，数据目录保留为 `%APPDATA%/email-manager/`，安装 appId 保持不变。显示名称统一为 **N7M - Custom Email Management**。

- 新资料文件：`email-vault.json`；备份：`email-vault.json.bak`。
- 首次设置软件密码时读取旧版 `email-data.json`，在完成加密写入及验证后移除旧版明文文件、临时文件和备份。
- 旧文件损坏时保留原文件，不覆盖、不清空账号。加密文件损坏时可保留原件后使用加密备份恢复。
- 清理旧版文件前比对加密保存的迁移指纹；旧版本后来新增或修改的资料文件会被保留并提示，不会静默删除或自动覆盖新版资料。
- 1.6 首次成功解锁旧版 scrypt 资料后，自动验证并升级为 Argon2id v2；有效的旧加密备份及迁移指纹也一并保留升级，损坏备份保留原件。升级后需使用 1.6 或更新版本，旧版程序不能读取 v2 资料库。请先退出旧版软件再使用新版。
- 账号数据不随免安装 EXE 一起移动。换电脑时，在关闭软件后复制加密资料文件，再用原软件密码解锁；浏览器 Profile 仍依赖目标电脑已配置的浏览器。

## 导入与导出

支持 Excel `.xlsx`、CSV、TSV、粘贴表格，含多工作表选择、导入预览、缺项提示、重复跳过。旧 `.xls` 请另存为 `.xlsx`。

不需要外部表格时，点击顶部“批量录入”直接填写多行账号。常用列为邮箱资料、浏览器、Profile、备注、分组、密码、TOTP；邮箱默认 150px，其余默认 80px，可拖动表头边线、使用方向键或展开“列宽设置”调整。编号自动生成，标签、冷却小时和启动网页保存后再编辑。支持增加、删除行、Tab 切换和矩形 TSV 粘贴；粘贴顺序与当前显示的七列一致。保存前统一校验，存在错误时保留整批内容，空浏览器保留为待完善。

点击“查看已有账号”可在同一录入窗口查询全部历史账号、筛选浏览器和分组、展开备注与业务资料；查询与收起面板不清空新账号草稿，历史凭据仅显示是否设置。账号按“邮箱资料＋浏览器＋Profile”去重：三项相同则跳过，同邮箱不同浏览器或 Profile 分别保存。邮箱资料只要求非空，可填写简称或部分内容。Chromium 的数字 Profile 与对应的 `Profile 数字` 等价；`Profile+21` 与 `Profile 21` 不同，Firefox 配置名区分大小写。

每次最多 1,000 行，密码和 TOTP 输入始终遮盖，普通密钥粘贴保留制表符、换行和前后空格；从密钥列开始的矩形粘贴须带有表格 HTML。未保存的录入内容在锁定时丢弃。

Excel 在独立工作线程中读取，可随时取消；锁定软件、关闭窗口或读取超过 15 秒时终止解析，不会保存部分账号。文件最大 20 MiB，最多 30 个工作表，每表最多 50,000 行、100 列，总计最多 250,000 个单元格、400 万字符，单元格最多 32,767 字符。ZIP 最多 512 项，单项实际解压最多 16 MiB、合计最多 64 MiB；超过限制会提示拆分文件。线程配置了 192 MiB 的 JavaScript 老生代堆限制，该值不是整个应用或系统内存的硬上限。CSV、TSV 和粘贴表格的行为保持不变。

推荐第一行表头，列顺序可以调整：

```text
邮箱链接,浏览器,Profile,编号,启动网页,备注,分组,标签,冷却小时,密码,TOTP密钥
user@example.com,Chrome,Profile 43,001,,工作用途,工作,"常用,项目A",24,,
```

兼容旧版无表头三列 `邮箱 / 浏览器 / 编号` 和四列 `邮箱 / 浏览器 / Profile / 编号`，支持 Tab 或逗号分隔、连续空列、带引号的逗号和多行备注。Excel 编号使用文本或 `000` 数字格式保留前导零。

**CSV 导出不包含账号密码或 TOTP 密钥**，仅导出普通账号资料。完整备份请保留加密资料库文件。

顶部“导出资料”默认提供加密完整备份 `.n7mbackup`，包含账号密码、TOTP、分组、备注及冷却设置，也可备份选中的账号。导出前复验当前软件密码，备份使用同一个密码加密，同时使用新的随机盐和 nonce；不会生成凭据明文文件。普通 CSV 仍可单独选择，且不包含凭据。导出目标不能覆盖活动资料库、内部备份或旧资料文件。

在同一窗口切换到“恢复备份”，选择文件并输入导出当时的软件密码；如果当前软件密码不同，取消“备份密码与当前软件密码相同”并输入当前软件密码。解密检查只显示数量，不向预览界面返回凭据。按邮箱资料、浏览器和 Profile 三项匹配已有记录，可只补齐空白字段、明确覆盖相同组合的资料，或者仅新增账号；恢复前检查并发修改，整批保存，保留现有账号的内部身份，新账号分配新的内部身份。同邮箱不同浏览器或 Profile 的密码不会互相覆盖。不会把源电脑的浏览器句柄或打开状态恢复到本机。备份文件最大 64 MiB，解密资料最多 40 MiB、10 万账号；预览授权 5 分钟后过期，锁定、密码变更、导航和窗口关闭都会撤销。

## 逐行批量修改

点击顶部“批量修改”，编辑当前筛选或已选的最多 1,000 个账号。先重新验证软件密码，再在同一表格逐行填写不同的邮箱资料、备注、分组、密码和 TOTP；密码与密钥始终遮盖。批量修改保留完整的十一列。软件只提交改变的字段，允许交换两个账号的邮箱资料，但不允许产生相同邮箱、浏览器和 Profile 的重复组合。保存前统一验证，任何一行失败都不会保存其他行；如果同一字段已在其他窗口被修改，会要求重新载入，未编辑字段的并发更新会保留。

编辑授权绑定当前窗口、账号范围和资料库解锁代次，5 分钟后失效；关闭窗口、重新锁定、系统锁屏、修改软件密码和页面导航都会撤销授权并清除编辑内容。正在打开的浏览器类型和 Profile 受保护，备注与凭据仍可修改。旧的批量统一赋值功能保留为勾选栏中的“统一设置”。

## 开发、验证与打包

需要 Node.js 22+。密码锁和加密存储在 Electron 主进程中运行，浏览器预览不提供明文存储后备方式。

```powershell
npm install
npm run dev
npm test
npm run test:ui
npm run dist:all
```

输出 Windows x64 三种分发形式：

- `release/N7M - Custom Email Management-1.8.1-Setup.exe`：安装版。
- `release/N7M - Custom Email Management-1.8.1-Portable.exe`：单文件免安装版。首次运行显示启动进度并准备运行文件，完成后保留运行文件缓存；同一版本后续启动直接复用缓存，重复点击会唤起同一个程序窗口。
- `release/N7M - Custom Email Management-1.8.1-NoInstall.zip`：解压免安装版。完整解压后运行同目录的主 EXE，保留 DLL、resources、locales 等配套文件，日常启动更快。

桌面流程测试使用独立目录、测试账号及隐藏窗口模式，不显示窗口、不抢焦点，且不实际启动浏览器或读写用户剪贴板；指定 `N7M_PACKAGED_TEST=1` 可通过相同版本 Electron 加载 `release/win-unpacked` 的打包 ASAR 运行同一套验证。隐藏模式只在同时指定 `N7M_TEST_BACKGROUND=1` 和隔离资料目录 `N7M_TEST_DATA_DIR` 时启用，普通软件启动不受影响。

Windows 窗口原生核心另有可选检查：设置 `N7M_NATIVE_WINDOWS_TEST=1` 后执行 `node --test tests/browser-windows-native.test.cjs`。检查在正常系统 PowerShell 中承载两个自有离屏窗口，验证同进程窗口分别关闭、身份防混淆和外部关闭检测；不启动真实浏览器、不聚焦窗口。测试注入层仅对自有夹具进程适配宿主路径，生产窗口身份及正常关闭代码保持一致。

## 启动优化（1.3.1）

单文件版不再每次启动都解压完整程序。运行文件缓存在 `%LOCALAPPDATA%/N7M/RuntimeCache/` 下，缓存按版本和构建内容区分，完成准备后才写入完成标记；中断的准备过程不会被当作可用缓存。启动器在准备期间提供进度，并阻止重复点击并发解压。

缓存只包含程序运行文件，账号加密资料仍保存在原来的 `%APPDATA%/email-manager/`。启动优化没有降低密码加密参数，也不会记住软件密码或跳过锁定。安装版和解压版同样精简了运行文件，并在应用初始化期间提供启动文字反馈。

Windows 打包通过 `build/build-windows.cjs` 使用缓存启动器模板 `build/portable-fast.nsi`。构建适配器只在当前构建进程替换固定版本 electron-builder 的 portable 模板，不修改 node_modules；升级打包工具时会检查兼容性，避免静默退回旧启动方式。

本机验证：旧单文件版两次启动到密码框为 28.35 秒和 26.38 秒；1.3.1 完整首次准备约 15.26 秒，0.84 秒内显示启动提示，完成缓存后再次启动约 0.72 秒。已验证准备窗口和正式程序最小化后重复点击都恢复原窗口，没有新增程序页面，缓存文件没有重新解压改写。构建适配器另有 `node --test build/launcher.test.cjs` 检查。

## 依赖维护与发布检查

`npm test` 同时运行应用安全、启动器、CI 权限与构建参数、依赖策略的回归检查。`npm run check:dependencies` 校验锁文件和已接受的精确依赖版本；`npm run check:dependencies:online` 额外向官方 npm registry 检查维护信息。例外清单与复核期限保存在 `security-audit/dependency-policy.json`。

2026-11-17 经开发者批准，XLSX 解析迁移到非官方、与原维护者无关联的 `exceljs-hardened 5.1.1`，修复已复现的原型污染问题；原有工作线程、解压和规模预算保持启用。现代依赖链单独使用官方 minimatch 11.0.9，旧构建链保留兼容适配。仍有 5 个弃用间接依赖；fork 的供应链信任和维护风险需持续复核，原期限 2026-12-04 不变。策略检查不会忽略漏洞扫描告警，也不会自动升级。详见本轮安全报告和 `security-audit/2026-11-17/` 的验证证据。

2026-11-16 复核发现 ExcelJS 的工作簿加载路径存在新披露的原型污染风险。开发者选择保留现有解析实现与线程限额，**仅导入来源可信的 Excel 文件**。隔离工作线程可避免污染主进程的原型，但不能保证导入数据正确，也不能代替上游修复；`npm audit` 当前无告警不表示此风险已消除。具体公告、可达性与决定见 `SECURITY-AUDIT.md`。

GitHub Actions 使用固定提交。构建任务仅有读权限；写仓库权限仅用于标签推送后的独立发布任务，发布任务不检出和执行项目代码。手动构建不发布。只读依赖检查工作流定期运行策略检查和 npm audit，不自动修改版本或创建发布。构建入口已固定禁止自动发布，CI 使用 `npm run dist:all`，不附加旧入口的 `--publish never` 参数。
